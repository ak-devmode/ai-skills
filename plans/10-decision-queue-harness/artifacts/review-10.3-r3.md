## BLOCKING (1)

- **10.3-r3-01** `scripts/driver-merge.py:332` (fail-open) — Satisfied requires only that SOME entry of a required name is satisfied. green is the set of names with any SUCCESS/SKIPPED/NEUTRAL rollup entry, and by_app (line 340) is the same per (name, app). A FAILURE or PENDING entry of the same name is therefore ignored. GitHub's rule differs: when a check run and a commit status share a required name, both are required. The check-runs endpoint can also return several latest runs of one name from one app across check suites, for example a workflow triggered on both push and pull_request for the same head. If one of those fails or is still pending, GitHub reports BLOCKED, and this code reads the BLOCKED as 'only reviews block' and merges with --admin past the failing required check. That is the r1-03 class (--admin past a required check that has not passed), now on the r2-05 satisfied() line. Note also: this is the fourth round in which the --admin precondition draws findings (r1-03, r2-03, r2-05, r2-06, now this). Re-deriving GitHub's protection evaluation client-side to justify a bypass is itself the convergence signal; narrowing --admin (e.g. only when the PR's sole unmet requirement is review approval, read from the GraphQL reviewDecision, with every rollup entry of every required name satisfied) or dropping it is the user's call. → A required (name, app) is satisfied only when at least one entry exists and EVERY rollup or check-run entry matching it is satisfied. Any non-satisfied entry of a required name means not satisfied. Add a test with a SUCCESS check run and a FAILURE status of the same required context, and one with two same-app runs where one fails, both expecting no --admin.
