## Phase 1: Contracts + deterministic scripts

### Task 1.0: Test entrypoint (first — everything below lands with tests)
- **Type**: AI
- **Action**: `scripts/tests/` with stdlib `unittest`; `python3 -m unittest discover scripts/tests`;
  add a `Test:` line to CLAUDE.md §6 so `/closeout` Step 3 detects it.
- **Acceptance**: the command runs (0 tests is a pass only until Task 1.2 lands); `/closeout`'s
  test-command detection finds it

### Task 1.1: Contract documents
- **Type**: AI+HUMAN_REVIEW
- **Input**: scope.md §4.1; brief §3.1–3.5; research §4a
- **Action**: templates under `templates/`, examples under `templates/examples/` (never inside a template):
  - `finish-conditions.md` — own revisioned file + changelog; row = check_id, owner (phase/unit),
    command or `judge`, repo, working dir, env, timeout (default 120 s), rung, unreachable-allowed + reason, evidence
  - verdict JSONL — run_id, run_state (`pending → judged → final`), resolved context, SHA(s),
    deployed version, finish-table revision, judge line; latest final run per check decides
  - gate semantics — runner rows: judge downgrade-only; judge rows: judge verdict is the result;
    required fail/inconclusive/pending blocks; declared-unreachable only; stale-SHA rejection vs per-repo base SHA
  - review dispositions JSONL — raw findings with stable IDs; every ID covered
  - evidence placement — class-A private only; permitted public verdict fields
  - feature map — index with status + evidence; four-H2 feature file; maintenance handoff format
  - adapter — doctor / env handle / verbs; CLI rules; exit codes 0/1/2/3
  - message contract — every runner / gate / `plans-index.py status` / judge-line message:
    what happened · why · cause class (code / environment / tooling) · next command · docs
    pointer, with actual values
- **Acceptance**: every contract names its reader and writer; a test generates each file from
  its template and finds no example rows; script tests (1.2–1.4) assert every emitted error
  message carries the message-contract fields

### Task 1.2: `scripts/resolve-identifiers.py`
- **Type**: AI
- **Action**: v1 kinds — env var, SSM path, proto field, route — against authoritative declaration
  files, namespace-aware; comment/fixture hits don't count; a new declaration in the same diff
  resolves. Prints `found · resolved · unsupported kinds`.
- **Acceptance**: `scripts/tests/test_resolve_identifiers.py` — comment-only name (fails),
  unrelated-proto name (fails), same-diff declaration (passes), fake env var (fails),
  unsupported kind reported, never green

### Task 1.3: `scripts/verify-run.py` (runner)
- **Type**: AI
- **Action**: execute each owned row's command in its declared repo / dir / env with its timeout;
  record resolved context + exit + output hash + ts + SHA + deployed version + finish-table
  revision as a `pending` run (JSONL, write-then-read-back like `dispatch-log.py`);
  non-executable → `inconclusive` + reason; timeout → `inconclusive: timed out after Ns`;
  refuse class-A evidence under a public repo.
- **Acceptance**: `scripts/tests/test_verify_run.py` — pass, fail, non-executable, timeout,
  wrong-repo context recorded, public-repo refusal, read-back failure exits non-zero

### Task 1.4: `scripts/verdict-gate.py` + index enforcement + base SHA
- **Type**: AI
- **Action**: gate over the latest *final* run per owned check (semantics above); `ledger-init.sh`
  records each repo's base SHA in the phase block; `plans-index.py status` runs the gate before
  writing Done; `plans-index.py validate` fails on a Done phase row without a passing verdict;
  judge ≠ codex appends `⚠ judge: <fallback>`, cleared by a later codex verdict; advisory flag.
- **Acceptance**: `scripts/tests/test_verdict_gate.py` — pass / missing / under-rung /
  fail-then-fixed clears / runner row downgraded blocks / judge row passes on judge verdict /
  pending blocks / undeclared-unreachable blocks / stale SHA rejected / hand-edited Done caught
  by validate / fallback marker set then cleared / advisory warns without blocking
