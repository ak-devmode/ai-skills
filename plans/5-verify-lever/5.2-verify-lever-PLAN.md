## Phase 2: `/verify` + `/review` on codex

### Task 2.1: `/verify` skill
- **Type**: AI
- **Input**: scope.md §4.2; Phase 1 contracts + scripts; `ready-to-clear/SKILL.md`
- **Action**: `verify/SKILL.md` (frontmatter per CLAUDE.md §3.1, no AskUserQuestion) = runner
  (`verify-run.py`) + codex judge in a read-only sandbox reading runner evidence + git for the
  unit's explicit revision range (empty range = failure). Own fresh probe (`codex --version` +
  `codex exec` ping), never gstack's. Judge header `codex <reported model> | claude-fallback
  <reason> | none <reason>`; no pinned model; every codex failure mode ends as a non-codex
  judge line, never a pass. Judge binds its verdict to `run_id` and finalizes atomically.
  Class B (scope + eng-review test plan, disposition coverage + rejection audit, `fixed <sha>`
  touches the finding's location, faithful-port rule), class A via runner, lenses, lever
  candidates (with `run_id` + scope), feature-map maintenance handoff.
- **Output**: `verify/SKILL.md`; `./setup.sh` re-run; README + ARCHITECTURE rows
- **Acceptance**: `lint-skill.py verify` clean; registers after restart

### Task 2.2: `/review` onto codex (spike first)
- **Type**: AI+HUMAN_REVIEW
- **Action**: (a) spike — codex on one real past diff (108.6 if available) with engine checks
  + Kalpa rules; record what codex cannot do. (b) extract `review/SKILL.md` §3 rules into a
  shared file; codex gate + local-maxima lens + silent-failure and dirty-comment flags; takes
  an explicit revision range (empty = failure); raw findings with stable IDs; Claude pass
  fallback only; write `review-<phase>.jsonl`.
- **Output**: spike note in `artifacts/`; updated `review/SKILL.md` (version bump) + rules file
- **Acceptance**: planted `|| true`, a workaround comment and an invented env var all caught;
  every finding ID has a disposition; a clean commit on `main` with an explicit range is reviewed,
  not reported empty

### Task 2.3: Verifier fixtures
- **Type**: AI
- **Action**: under `verify/tests/fixtures/`: known-bad scope (invented env var, over-built
  abstraction, rejection with no reason, missing evidence, row under its rung, dropped finding
  ID), clean controls, and repaired copies of each defect. Run from the test entrypoint.
- **Acceptance**: each defect yields a finding that names it; controls and repaired copies pass;
  `judge: none` fails the suite (an always-failing or absent judge cannot satisfy it).
  `/verify --demo` runs this fixture scope in ~1 minute and prints a failing verdict naming the
  planted defects plus a passing control — the teammate's first contact with the gate
