## Phase 3: Wiring + self-heal + rollout

### Task 3.1: `/scope` wiring
- **Type**: AI
- **Action**: `/scope` writes `finish-conditions.md` (not into `scope.md`); each row names its
  owning phase/unit; commit-producing phases carry review + verify tasks, commit-less phases
  verify only; plan stubs inherit them.
- **Acceptance**: a fresh `/scope` dry run emits the file with owners and the per-phase tasks

### Task 3.2: `/plan` wiring + self-heal
- **Type**: AI
- **Action**: `ledger-init.sh` records per-repo base SHA at phase start; `/review` per
  commit-producing unit and `/verify` per unit at checkpoints, both given `base..HEAD` per repo
  (empty = failure); gate via `plans-index.py status`; **advisory mode** until 3 real scopes pass
  cleanly, then blocking; `--skip-verify "<reason>"` loud in header + index. Self-heal: no
  `finish-conditions.md` → draft from the scope's deliverables, Alex confirms once.
- **Acceptance**: recipe in `plan/tests/verification-recipes.md` — an old scope heals; a failing
  verdict marks (advisory) / blocks (blocking); skip is visible in the index; a direct-to-main
  unit is reviewed with its explicit range

### Task 3.3: `/closeout` wiring + ledger-template fix + lever backlog
- **Type**: AI
- **Action**: verdict present + complete, else run `/verify`. Failing/blocked final verdict →
  no HEALED; archive still runs; index `✅ Done — ⚠ verify failed <check_ids>`; failed checks to
  TO-DO.md. Feature-map maintenance handoff written to the scope's artifacts (never edits the
  private test-suite). Lever candidates → `## Lever candidates` in the project's `plans/TO-DO.md`
  with `Touches:`, `run_id`, scope; only a different scope/run counts as a second sighting.
  Inherited item: `templates/closeout-prep.md.template` examples → `templates/examples/`;
  `ledger-init.sh` output tested for zero example rows.
- **Acceptance**: fresh ledger has no example rows; closeout with no verdict runs `/verify`;
  closeout on a failing verdict archives with the ⚠ row and no HEALED; re-running closeout
  doesn't flag a second sighting; a real repeat from another scope does

### Task 3.4: Rollout
- **Type**: AI+HUMAN_REVIEW
- **Action**: `./setup.sh` checks Python ≥ 3.9 and codex (installed, logged in, runs) and
  **warns** with exact fix commands, never failing the pull. README "Verification" section:
  what `/review` + `/verify` do, prerequisites, what each ⚠ means, advisory vs blocking,
  `--skip-verify`, reading a verdict, `/verify --demo`. `/verify` and `/plan` print one line
  when the local ai-skills clone is behind `origin/main`. ARCHITECTURE / CLAUDE.md updates;
  lint-skill fleet pass; team announcement (CLAUDE.md §2.1): `git pull && ./setup.sh`, restart,
  `/verify --demo`, "set up codex or your verdicts carry a ⚠ in the index"; confirm nothing
  requires herdr.
- **Acceptance**: fresh-clone walkthrough `git pull && ./setup.sh` → restart → `/verify --demo`
  under 5 minutes; setup without codex warns with the fix and exits 0; fleet lint 0 ISSUE;
  `python3 -m unittest discover scripts/tests` green; announcement drafted for Alex
